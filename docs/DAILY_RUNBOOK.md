# Complete English — Daily Publishing Runbook (v2)

Read COURSE_SPEC.md and course.config.json before creating any lesson. This runbook describes the scheduled execution and source-of-truth workflow.

## Repository structure

Repository: alextgtome/complete-english; publishing branch: develop.
- docs/COURSE_SPEC.md — canonical pedagogical and UI requirements.
- docs/DAILY_RUNBOOK.md — daily publishing procedure.
- course.config.json — machine-readable duration, start date, timing and historical exceptions.
- data/generation-index.json — **compact derived planning index**: all chunk IDs/phrases/first-use days, all lesson topics, and the latest seven lesson contexts. Read this first when planning. Generated by scripts/build-generation-index.mjs.
- data/lessons.js — full canonical JavaScript registry (window.CE_DATA). Read this only when editing/publishing a day or auditing discrepancies, not automatically at the beginning of every planning run.
- lessons/day-NNN.html — thin page for one day's lesson, referencing shared assets.
- assets/app.js and assets/site.css — shared rendering and interactivity.
- scripts/validate-lessons.mjs — automated checks.
- .github/workflows/pages.yml — validation **before** Pages deployment.

The root index is generated from data/lessons.js; do not add a redundant hardcoded list of days. The browser's localStorage is NOT synchronized with GitHub.

## Daily run (in order)

1. Compute Day N using the current **America/Sao_Paulo calendar date** and 2026-10-29. Do not publish outside days 1–150.
2. Through the authenticated GitHub connection, read COURSE_SPEC.md, this runbook, course.config.json and **data/generation-index.json**. This compact index contains all existing chunk phrases and true first-use days plus the last seven lesson contexts. Do not initially load data/lessons.js, past HTML or assets/app.js merely to choose a lesson topic.
3. **Idempotency first:** compare planned Day N to the latest day in the index; if already covered, check the registry and today's HTML, verify and link the existing lesson without duplicating it. If index and registry disagree, stop and investigate. The index is derived, not authoritative.
4. Check FULL chunk history: compare normalized spelling and semantic meaning; select exactly three genuinely new IDs, three spaced reviews with verified first-use days, a novel topic and one foundations skill. Keep the last seven days' themes varied. **From Day 18, follow the 3+2+2 scenario rotation:** modulo seven (0,3,6) = Everyday; (2,5) = Workplace/Engineering; (1,4) = Interview. This applies only to the main 15-minute speaking segment, not to the 10-minute everyday small talk, which stays EVERY DAY. Preserve at least two weekly workplace sessions for hands-on English: deployment and rollback, AWS service choices, API architecture and contracts, messaging, code reviews, standups, integration and trade-offs. Alternate these topics and require genuine technical explanation plus realistic spoken communication. Do not turn all days into technical interviews or dilute technical workplace practice.
5. Build one complete lesson obeying the 15 + 35 + 30 + 10 timing and both speaking routes. All six chunks include their own PT-BR translation and "Quando usar"; all other user-facing instructions are English. Within the existing small-talk time, add an **unexpected non-technical question** and practise the scaffold **honest answer → simple detail → optional question back**. Include rapid unrelated daily-life reflex questions. If the learner has no plan, accept uncertainty rather than inventing a story. On Everyday days choose varied settings from food, weather, family, weekends, hobbies, errands, travel, invitations and preferences. On Workplace days, require a concrete engineering task and natural interactive follow-up. Record `scenario_type` in the new day metadata and verify it matches the rotation defined in course.config.json.
6. Design exactly THREE cumulative substitution sequences. Each needs one natural base, 4–6 concrete cues and fully grammatical, coherent intermediate results. Change grammatical units together if needed; attach short note to linked changes. Simulate and **proofread every resulting sentence**, including agreement and idiomatic usage. Never "fix" an intentionally wrong intermediate model answer in the following cue.
7. **Only now read data/lessons.js** (the complete source), append three new G entries and one Day N record with six IDs, date, prompts and fields required by shared UI; add focusDrills[N] and preserve history. **Regenerate data/generation-index.json from the updated registry in the same change**, using scripts/build-generation-index.mjs or equivalent deterministic logic. Do not hand-invent historical index entries.
8. Add lessons/day-NNN.html using the neighboring thin template and referencing shared data and assets. Ensure the shared frontend can render this record; don't embed a second lesson copy in HTML.
9. Check everything locally if possible: node --check assets/app.js; node scripts/build-generation-index.mjs --check; node scripts/validate-lessons.mjs. The Pages workflow requires all three before deploying. Regeneration and registry edits are one logical atomic change. **Never skip a failing check**, and never claim success based on a commit alone.
10. Commit with authorized GitHub operations and verify the resulting file reads. Check Pages deployment status separately; only link the public URL as confirmed if its deployment succeeds. Otherwise link the GitHub file and explain the status.
11. Deliver a useful concise English lesson summary with the date, time blocks, three new and three review chunks (including their PT-BR translations and "Quando usar" cues) and a real link to the published lesson. Do not claim speaking/writing performance without samples.

## Failure policy and maintenance

- Can't read GitHub registry/spec? Do not assume new chunks are unprecedented; do not blindly publish or create duplicate lessons. Explain the obstacle, provide useful unverified learning material in chat if appropriate.
- Validator fails? Correct the SOURCE first. Do not disable the Pages quality gate to publish.
- Rerun on the same day? Return the existing day's content and no duplicate.
- Found a design bug? Fix the shared assets, not 150 separate lesson HTML files.
- Found a content bug? Fix the registry, regenerate the compact planning index and add regression tests. Do not edit the index alone, because it is derived from the registry.
- Keep changes additive and auditable. Do not commit personal responses, notes, recordings, private data, credentials or secrets to this public repository.
- Changes to the pedagogical approach belong in COURSE_SPEC.md, not appended to the ChatGPT automation prompt. Only change the automation prompt to update its short reference or operating boundaries.
